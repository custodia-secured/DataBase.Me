**Status:** closed 2026-10-25. The first CI run on GitHub passed every job, including the launch

## Plan

**Scope (handoff brief §8):** monorepo, Tauri shell, CI on Windows/macOS/Linux (fmt, clippy
`-D warnings`, eslint, typecheck, tests, build, licence check, DCO check), LICENSE files,
GOVERNANCE.md, CODE_OF_CONDUCT.md, CONTRIBUTING.md, FUNDING.yml, issue templates, FORMAT.md draft,
ADR-0001 to ADR-0008.

**Acceptance:** the app launches on all three OSes in CI; CI is green; unsigned commits fail the
DCO check.

**Tasks.**

1. Cargo workspace (`dbme-core`, `dbme-cli`, `dbme-desktop`) with a pinned toolchain and workspace
   lints that enforce the coding standards (no `unwrap`/`expect` outside tests, documented public
   APIs, no `unsafe`).
2. pnpm workspace: the desktop web UI (React 19, Vite 8, TypeScript 6 strict), `@databaseme/ui`
   (design tokens, light and dark), `@databaseme/sdk` (reserved, Apache-2.0).
3. Tauri 2 shell with a strict CSP, deny-by-default app commands, and a smoke-test mode so CI can
   prove the app launches and its UI renders.
4. Scripts: DCO check (with tests against a real repository), JS licence check (with an SPDX
   expression evaluator and tests), launch test.
5. CI workflow: `dco`, `web`, `cargo-deny`, `js-licences`, and `desktop` on three OSes.
6. Licences, governance, contribution, conduct and security documents; FORMAT.md draft;
   ARCHITECTURE.md; ADR-0001 to ADR-0010.

**Risks.**

- Tauri needs a C++ toolchain and per-OS system libraries; CI installs WebKitGTK 4.1 on Ubuntu
  22.04 to test the oldest supported Linux.
- Launching a GUI app on CI runners: handled with a smoke-test mode and `xvfb-run` on Linux.
- Licence noise from transitive dependencies: handled by an explicit policy (ADR-0009).
- Very new tool versions (TypeScript 7, ESLint 10, Vite 8, pnpm 12): TypeScript held at 6.0 because
  typescript-eslint does not support 7 yet (ADR-0001).

**ADRs:** 0001 to 0008 as the brief lists, plus 0009 (dependency licence policy) and 0010 (desktop
shell security baseline), which M0 needed.

## Deviations and decisions to confirm

1. **AGPL-3.0-or-later.** The brief says "AGPL-3.0"; ADR-0004 reads it as the "or later" form.
   Easy to change now, hard after outside contributions arrive.
2. **TypeScript 6.0, not 7.0**, because typescript-eslint does not support 7 yet (ADR-0001).
3. **Two extra ADRs:** 0009 (dependency licence policy) and 0010 (shell security baseline).
4. **Licences beyond the brief's list,** each justified in ADR-0009: `Unicode-3.0` and
   `Apache-2.0 WITH LLVM-exception` in Rust; `BlueOak-1.0.0`, `CC-BY-4.0` and `CC0-1.0` in JS
   build tooling only.
5. **Crates and packages are created when their milestone starts**, so `crates/store`, `mirror`,
   `ingest` and the others, and `packages/views` and `recommender`, do not exist yet.
6. **App identifier `org.databaseme.desktop` is provisional** until the trademark and domain check.
7. The desktop crate builds only as a Rust library plus binary for now; the extra library types and
   mobile entry point that iOS and Android need are added in M14.

## Known issues

- WebView2 prints `Failed to unregister class Chrome_WidgetWin_0` when the app exits within a second
  of starting (smoke mode). It is harmless.
- CI startup times are only in the job logs, which need a GitHub sign-in to read. Writing
  `startup_ms` to the job summary is a small follow-up.
- GitHub Actions are referenced by version tag, not commit SHA. Pinning to SHAs (with Dependabot
  keeping them current) is a follow-up.

## Proposed plan for M1 (vault and object core)

- `crates/store`: SQLite schema as migrations (rusqlite, bundled, FTS5), `application_id` and
  `user_version`, WAL; the blob store with BLAKE3 and deduplication; all SQL as prepared statements.
- `crates/core`: ULIDs, fractional sort keys, the object, type, field and relation services, the
  hash-chained op log with undo and redo, and the seeded system types.
- Typed IPC from Rust: commands and an event stream, TypeScript types generated (ADR choosing ts-rs
  or tauri-specta).
- Tests: at least 90% line coverage on `core` and `store` (cargo-llvm-cov in CI), proptest for the
  op log, a criterion benchmark for 10k-object create, edit, delete and undo under 2 s, and a test
  that kills the process mid-write and then opens the vault cleanly.
- CI: cross-compile `core` and `store` for `aarch64-apple-ios` and `aarch64-linux-android`.
- ADRs: IPC type generation, op log hashing and canonical encoding, fractional index algorithm,
  migration policy. FORMAT.md sections 3 and 5 move from Draft to Decided.
