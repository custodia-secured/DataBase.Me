### What exists already

- A registry of five views (`packages/views/src/registry.ts`), each given one object and `onOpen`.
  The pane shows them as tabs (`apps/desktop/src/App.tsx`), which will not fit 360 px at thirteen.
- `Source` is a parent's children or a type's objects; `SourcePicker` chooses one; `usePage` and
  `useCount` read pages of it; the DSL has conditions, sorts and one-hop `related_to` (ADR-0020).
- Saved views are stored and go through the op log: the `views` table and `view_save`,
  `view_update`, `view_get`, `view_delete`, with `renderer`, `query_json`, `config_json` and
  `owner_object_id`. Nothing in the UI uses them yet except the export, and the Table's and
  Gallery's settings last only for the session.
- `objects` has `event_start`, `event_end`, `geo_lat` and `geo_lon`. The DSL can name the event
  columns but **not** the geo ones. EXIF import and the files folder write geo; no surface in the
  app edits it.
- `canvas_items` is only reserved in FORMAT.md; there is no table. The DSL has no aggregates, only
  `facets` on one field. There is no way to read the whole graph in one call.
- The CSP is strict and static: `script-src 'self'`, `style-src 'self'`, `connect-src ipc:`, and
  workers fall back to `'self'`. There is no `unsafe-eval`, no `blob:` worker and no remote host.

### Design (ADR-0031 the view framework, ADR-0032 charts and aggregates, ADR-0033 the map and the network, ADR-0034 the graph, ADR-0035 the canvas)

- **The view framework.** Every new view is loaded with `React.lazy`, so Vega, MapLibre, Sigma and
  Excalidraw each stay in a chunk of their own and cold start does not pay for them. The tabs become
  the current view's tab, the few most used and a "Views" menu; on a phone, the menu alone. Each
  view's settings (the source, the filter, the field it groups or dates by) are one typed object in
  `config_json`. Settings last for the session until the person presses **Save view**; saved views
  of an object are listed in a bar shared by every view, the Table and Gallery included. The mode
  remains a filter on the registry.
- **The filter editor** writes DSL conditions: one row per condition (field, comparison, value),
  shared by every view that reads a source.
- **An accessible alternative for every view** is a real one, reached by a "Show as list" switch in
  the same place on each view and kept with the view's settings: the same objects as a keyboard grid
  or list with what the picture encodes written out in columns. Reduced motion is respected, and
  no meaning is carried by colour alone.
- **Kanban.** Columns are the options of a select field, plus "No value". A column is a virtualised
  list read in pages. Moving a card sets the field and the order through the op log, so undo works
  and the files folder follows. Drag with dnd-kit (already here) and move by keyboard, with an
  announcement. On a phone, one column at a time with the others a swipe away.
- **Calendar.** Month and week, by `event_start` or any date field. Only the visible range is read,
  with a bound per day and "+N more". Grid semantics for the keyboard. Moving an item changes its
  date. On a phone, an agenda list.
- **Timeline.** A custom virtualised lane over a date field or `event_start`–`event_end`, zoomable
  from days to decades, with counts per bucket read by aggregate when zoomed out. On a phone,
  vertical.
- **Charts.** Vega-Lite as the stored spec, drawn by `vega-interpreter` so that no `unsafe-eval` is
  needed (gate 1a). Numbers come from a new `aggregate` store call: group by one or two fields with
  time bins, count, sum, average, minimum and maximum, computed in SQL with a bound on buckets
  (build plan §2.7: aggregate in SQL before rendering). The alternative is the table of those rows.
  ECharts stays out unless a gate shows the need, so Sankey, treemap and sunburst wait (Decision 3).
- **Dashboards.** A saved view with the renderer `dashboard` whose config is a grid of tiles, each a
  saved chart or view, one column on a phone. A failure in one tile stays in that tile.
- **The recommender.** `packages/recommender`, plain TypeScript with no React: `recommend(profile,
goal?)` ranks renderers by hard constraints (a calendar needs a date) and soft scores (the
  Cleveland–McGill ranking), and every result carries one sentence saying why. A new `profile`
  store call gives each field's kind, cardinality, share of empties and range, with the object
  count and what has geo, relations or children. It appears as "Suggested" in the Views menu and
  never switches a view by itself.
- **Map.** MapLibre GL over a basemap shipped in the app (Natural Earth land at 1:110m), so a map
  works offline and asks for nothing; a local PMTiles file can replace it, read over IPC. Points are
  clustered, and the alternative lists places with their coordinates. Locations are set by a click
  or typed; there is no geocoder, since that would be a network request. The DSL gains `$geo_lat`
  and `$geo_lon`. Remote tile URLs wait (Decision 5).
- **The graph.** Sigma.js and graphology over a new `graph` store call: compact arrays of nodes and
  edges, relations and parent links, for a source or the whole vault. Nodes start at positions
  derived from their IDs, so the first frame does not wait for a layout; ForceAtlas2 then runs in a
  worker and can be paused. The alternative is a searchable node list with each node's neighbours,
  which is also where `related_to` with depth is used. On a phone, the list comes first.
- **The canvas.** Excalidraw if gate 1d admits it, with object cards embedded in the scene. Migration
  5 adds `canvas_items` as FORMAT.md reserves it, one row an element, written through the op log. A
  card is an element with an `object_id`. The alternative lists the cards with their positions and
  moves them by keyboard. If the gate fails, the same table is drawn by React Flow, already here,
  with cards and freehand strokes, and an ADR says so.

  the labelled set and fails under 0.8.
- _Accessible alternative and phone layout for each view:_ `kanban`, `calendar`, `timeline`,

  the view and on its alternative, in both themes, and the same action done by keyboard alone.

  and a non-blank canvas; time to first frame gated on Edge, printed on WebKit.
- _Nothing regresses:_ the zero-network gate and `fixtures.ts`'s origin check keep running; cold
  start is measured again at close-out against M7's figures, since lazy loading is meant to hold it.

**Risks.**

- **Excalidraw and the CSP.** It is the largest dependency in the plan and its fonts and styles are
  the likeliest conflict with `style-src 'self'`; hence its gate and a stated fallback.
- **WebGL on shared runners.** Software WebGL may make the 100k budget meaningless on CI, or
  WebKit may not offer WebGL at all. Then "renders" is gated where it can be and the figure on real
  hardware is recorded.
- **"Expert-labelled" fixtures.** Nobody independent has labelled anything (Decision 7).
- **Size of the milestone.** Eight views is more surface than any milestone so far. Each view is its
  own task and lands green, so a stop between them leaves `main` whole.

## Decisions to confirm

Each has a default, and work proceeds on the default until the owner says otherwise.

1. **Modes.** Build plan §5 puts kanban and calendar in Organizer, graph in Researcher and charts in
   Data/Power, and neither of the last two exists. Default: Simple is unchanged and Organizer shows
   all of M8 until those modes are built.
2. **Canvas storage.** One `canvas_items` row per element rather than a scene blob in `config_json`,
   so undo, the op log and a later merge see single elements.
3. **ECharts stays out of M8.** Vega-Lite covers the common charts and is the serializable spec;
   Sankey, treemap and sunburst wait for a need.
4. **Graph edges** are relations and parent links; the layout is not stored and is computed again.
   Cytoscape.js (optional in the plan) stays out.
5. **Remote map tiles wait.** The plan says "user-chosen tile sources", and the CSP's `connect-src`
   is static, so a tile URL needs either a looser CSP or a request made through the shell. M8 ships
   the bundled basemap and local PMTiles only, and ADR-0033 records this as a deviation.
6. **No geocoder.** Locations are clicked or typed.
7. **The recommender's fixtures.** The brief asks for agreement with labelled fixtures and the plan
   for an "expert-labelled" set. Default: I write the set from published guidance (Cleveland–McGill,
   the Draco and Voyager work) before writing the rules, and the acceptance line says plainly that
   the labels are the author's. **Needs the owner if it should mean more:** an independent labeller.
8. **Saved views are explicit.** Settings last the session until "Save view"; nothing is saved by
   looking at something.

owner's release steps.
