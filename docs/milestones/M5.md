**Design (ADR-0021).**

- **A replica that commits through the store, like a second device** (ADR-0006 17-18):
  `crates/mirror` (`dbme-mirror`) depends on `dbme-core` and `dbme-store`, never on the shell;
  outside edits become ordinary ops through the `Txn` services, one file per transaction.
  **Provenance is the device, not a column (Decision 1):** the chain hashes `device_id`
  (`chain.rs:69-86`) and `Txn::begin` takes a `Context` (txn.rs:199), so the mirror commits under a
  second `Context` with the same `actor_id` and a derived `device_id`: no `ops` column,
  tamper-evident, sync-ready.
- **Undo (Decision 2, a flagged deviation).** Brief 145, ADR-0006 18 and build plan 365 say undo
  works as usual for outside edits; proposed `Vault::transact_external` commits like `transact`
  (vault.rs:298-313) but leaves the undo stack alone, as a second device's ops would. The cost,
  stated in ADR-0021: an app edit to a block the file also changed becomes `UndoBlocked` and the
  step is dropped (vault.rs:330-337); the block-wise merge limits that to blocks both sides touched.
  `conflict_resolve` and `mirror_hold_decide` use `transact`.
- **No watcher and no timer inside the engine.** It takes `FileEvent`s from a `Watcher` trait
  (ADR-0006 49-50: platforms without one rescan **on resume**) and offers `rescan()`, deriving the
  same events from size, mtime and hash; `pump_out()`, `pump_in(events)`, `is_quiet()`. **One**
  debounce, owned by the caller, 300-500 ms; the `notify` debouncer only stitches rename pairs. File
  I/O is one trait: `std::fs`, **in-memory**, counting.
- **The hook on the app side.** The shell's notifier (`crates/api/src/lib.rs:140`) wakes a worker
  thread that drains a **`mirror_dirty`** table written in `Txn::finish` by a new
  **`note_mirror(op)`**, not from search's `touched`, since `note_search` (txn.rs:281-301) skips
  moves and every Relation, ObjectType, Attachment, Type and Field op, all of which change a file.
  `note_mirror` marks the owning object of every op, `src_id` for relations, and on a title change
  or move every `src_id` in `relations_touching` (txn.rs:675) of the subtree, since wikilinks name
  paths; a Type or Field rename sets `full_rewrite_needed`. The insert is gated on a `Context` flag.
- **Migration 3** (no ops, so the CLI's "25 ops" test holds): `mirror_state` per FORMAT.md 186 plus
  `path_key` (unique; NFC + case-folded, since NTFS and APFS are case-insensitive), `file_size`,
  `file_mtime_ms`, `state` (`synced`, `pending`, `held`, `excluded`, `trashed`; the row survives
  Trash); `mirror_dirty`, `mirror_meta`; `conflicts` per line 187 with `object_id` nullable,
  `rel_path`, `resolution` and the kinds `edit_delete`, `invalid_value`, `duplicate_id`,
  `dropped_file`. **No foreign keys**, like `search_dirty`: a replayed permanent delete would
  otherwise fail `verify`'s `foreign_key_check` (verify.rs:91-102); `mirror-check` sweeps orphans;
  none is op-logged or in `verify::TABLES`.
- **Paths.** FORMAT.md §6.1 is normative; top-level objects stand where `<Space>` will. Its open
  rules, proposed (Decision 5): a taken `path_key` gets ` (2)`, ` (3)`, …; names cut to 120 bytes
  and `rel_path` to 200 (other tools' 260-character limit bites first), both measured with the
  240-character fixture path. Ignored: every dot-path but `.dbme/`; temp files are dot-prefixed and
  never `.md`.
- **Frontmatter.** §6.2's envelope: `id`, `types`, `tags`, `created`, `updated`, `fields:` (Decision
  4, gate 1h; nested maps are said to show as unsupported in Obsidian's property editor, recalled),
  `relations:` by field key with `{id, link}`, the ID winning, and a new **`links:`** list (`id`,
  `link`, `type`, `label`, `props`, `block`) for relations with no field (FORMAT.md 111, 137), so
  "every relation" is reproducible (8b). The seven unlisted `objects` columns get same-named keys
  (6); `sort:` carries `sort_key`, an inbound change being a `move_object` (7); `updated:` is
  informational. Other top-level keys round-trip verbatim through `props_json._frontmatter` (10b).
  **Per kind (§3.3):** scalars decoded by the field kind (from `.dbme/schema.json` on rebuild),
  look-alike strings and `select` IDs quoted, maps for the structured kinds. `tags:` and body `#tag`
  become `tagged` relations to `Tag` objects by title (5b). `mentions` are never written.
- **Body.** The round trip is normalising (blocks are `content_json`, `crates/core/src/block.rs`).
  Every block carries a trailing `^<id>` anchor (8): on the line for paragraphs, list items and
  quotes; on its own line after a heading, fence, divider or table (Obsidian is said to reject one
  on a heading line, recalled; gate 1h); a lone `^id` line attaches to the preceding block. Children
  indent two spaces per level, reparented by indentation (11b; gate 1h). `image` is
  `![[attachments/<hash><ext>]]` (9). A mention is written `[[<path>/Title]]` **always** (FORMAT.md
  368; paths are unique); `|shown`, `#^id` and `![[…]]` keep `shown`, `block` and `embed` as
  optional keys on the mention run, which `check_run` (block.rs:190) forbids today: an ADR-0016 note
  (10). A wikilink resolving to one object is a mention, to none text; unknown kinds ride in a
  `dbme` fence; an empty paragraph is its anchor alone (11).
- **Identity and inbound rules** (ADR-0006 30-44). Identity resolves `id` → path → content hash
  within the batch → new. **Nothing is trashed on an inference** (12): a known path without `id` is
  the same object, `id:` is written back, `missing_id` is informational. An unknown `id` is adopted
  (13); one matching a **trashed** object is `restore_object` then merge; a duplicate `id` on
  another live path is re-issued (13). Rename → title; a moved file or folder → `move_object`.
  Deleted file → `trash_object` of **that object only**, its remaining children reparented to the
  grandparent first (27), since `trash_object` trashes the subtree (txn.rs:623-636). A trashed
  object's file moves to `files/.dbme/trash/<id>.md` and returns on restore (16b). Non-`.md`: a
  referenced attachment becomes a blob and image block; anything else is **the basic drop zone**, an
  object typed by MIME with the blob attached, no extraction (15). First enable treats a same-`id`
  pair as both-changed against an empty base (20b).
- **Merge and conflicts (Decision 17).** The merge is on the **model, not the bytes**: with base B,
  file F and object A, frontmatter field by field and the body per block id (one side changed → take
  it; both → `diffy::merge` inside that block, a conflict only when that fails; blocks on one side
  are inserts or deletes), so formatting never reaches the merge. **An inbound apply writes nothing
  back**; only an app-side op rewrites. Values are validated before `begin`, a bad one becoming
  `invalid_value`, since `Txn::guard` is sticky (txn.rs:326-332) and `check_props` (txn.rs:521)
  would fail the whole file. On a true conflict the app's version stays; the file's becomes a
  conflict-copy **Note** (frontmatter in `conflicts.details_json`, raw bytes in the `BlobStore`),
  and only after it commits is the file rewritten and the copy given its own file (16).
  `edit_delete` is a conflict. `parse_error` leaves the file untouched and **holds** the object's
  pending writes. Cloud-conflict names: Dropbox's is documented (build plan 371), the others come
  from gate 1i. **Echo prevention:** `mirror_state` is updated only **after** the rename (a crash
  leaves a stale hash the next rescan resolves), and an in-flight ledger of expected hashes, removes
  and renames marks the app's own events. A Windows sharing violation (`crash.rs:45`) gets ten
  retries, then `pending`, never a drop. Sensitive objects default to `excluded` (9b).
- **Bulk-change guard (Decision 3).** Brief 154 and ADR-0006 40 say "more than 50 or more than 10%";
  the acceptance says 50 deletions trigger it, which must hold at any folder size (under 500 files
  50 is already over 10%), so the count rule is `>= 50` (an ADR-0006 note), proved on 1,000 files.
  The percentage rule stays `> 10%` with no floor. Rewrites count per batch; deletes may later use a
  60 s window, so no test forbids that. A hold applies nothing, writes one `bulk_change_hold` row,
  keeps writing unrelated objects, and resolves by `Proceed` or `Restore`.
- **Export and import (Decision 18).** `crates/export` (`dbme-export`) writes FORMAT.md §7:
  `types.json`, `views/<id>.json`, `data/<Type>.csv` with multi-valued cells as JSON arrays. Those
  cannot be lossless, so the full export adds `ops.jsonl`, `vault_meta.json` and `blobs/`; the
  import is `Vault::create_from_ops`: an empty database under the exported `vault_id`, the ops
  replayed as `verify` does, **without** the 25-type seed, which reproduces the hash chain.
  `files/.dbme/schema.json` (the content of `types.json`) is written by `core/files`, which the
  rebuild needs first (19).
- **Commands, events, location.** Eight one-line Tauri wrappers (`mirror_*`, `conflict*`,
  `export_run`) in the five places `commands_are_declared_everywhere`
  (`apps/desktop/src-tauri/src/ipc.rs:611-616`) checks: 45 becomes 53. Inbound commits fire
  `vault-changed`; `mirror-changed` carries status and inbox. The folder defaults to `files/`; the
  override lives per vault ID beside `identity.json` (`app_dir`), not in `vault_meta`, since a
  machine path inside a portable vault breaks when it moves (20; FORMAT.md §6 says so). A typed path
  in M5, the picker in M7. On an encrypted vault the folder is off and enabling it warns (ADR-0006
  47-48; SECURITY.md 35-36), tested behind a flag.
- **Crates** (own ADR each; versions and licences from the crates.io API on 2026-11-02, re-checked
  at gate 1a; the survey is the appendix below): `pulldown-cmark` 0.13 (MIT), no default features,
  embeds **not verified** (gate 1b); `saphyr` 0.3 (MIT OR Apache-2.0), pure Rust, duplicate keys and
  quoting **not verified** (1c); `diffy` 0.5 (MIT OR Apache-2.0), inside one block, CRLF behaviour
  **not verified** (1d); `notify` 8.2 with `notify-debouncer-full` 0.7, in `crates/mirror` only.
  **`notify` is CC0-1.0**, which `deny.toml`'s allow list (21-33) lacks and ADR-0009 line 26 admits
  for JS tooling only: an `exceptions` entry (line 35; syntax recalled), an ADR-0009 row, the
  justification in ADR-0024 (21).
- **Budgets.** Each under 2 s at 10,000 objects, debounce included; release tests on
  `budget.rs:54`'s pattern, best of three with the worst printed (M4 did one machine, best of
  three); gated on `ubuntu-latest`, **printed, not gated, on `macos-latest`**, Windows by hand. The
  10,000-case run is its own release step (22).
- **Fixtures.** `obsidian/` with `links.json` naming every link and target, the vendors' conflict
  names, a case-only pair, nested lists, a PNG; `obsidian-roundtrip/`, the golden; `malicious/`:
  oversized frontmatter, traversal in names, `id` and embeds, a junction out of the root, `CON.md`,

**Tests** (every acceptance item names its test):

- _app→file and file→app each < 2 s:_ `budget.rs`, release, 10,000 objects; app→file polls for the
  edit's token, file→app uses the real watcher and `recv_timeout(2 s)`.
- _10,000 interleavings lose zero content:_ `interleavings.rs` on the in-memory filesystem. A case
  is a random sequence of app edits, file edits, pumps, rescans, ticks and undos; the generator
  never produces unparseable files (those are `inbox.rs`) and **tracks expectations**: a later
  same-side edit of the same target, or an `Undo`, supersedes the earlier token. At quiescence every
  expected-live token is in the live object, a conflict copy its `edit_edit` or `edit_delete` row
  names, or the Trash; no op carries a value no side wrote; every live object renders to its file's
  parse; `verify(true)`; mirror ops carry the mirror `device_id` and app ops do not; nothing outside
  the root; each `Undo` succeeds or returns `UndoBlocked`.
- _no echo loops:_ `echo.rs` on the counting filesystem: own writes, removes and renames produce no
  op and no second write over a hundred cycles; a "hostile editor" that reorders keys and switches
  line endings produces neither; the serializer fixpoint.
- _files-folder merging (brief 282-283):_ `merge.rs` in core: the three identities, disjoint-block
  edits always clean, a conflict only when one block differs three ways.
- _deleting 50 files triggers the guard:_ `guard.rs`: 50 `Removed` in one batch and as one
  `rescan()` on 1,000 files; 51 rewrites; 49 of 1,000 not held; 1 of 3 held; writes during a hold;
  both resolutions.
- _rename/move = rename/reparent:_ `moves.rs`: rename, move, folder move with descendants,
  `Removed` + `Created` in one batch and across two, case-only rename and collision on three OSes,
  parent deleted with folder left, trash and restore both ways.
- _Obsidian fixture opens with working links:_ `obsidian.rs`: in (every `links.json` link a relation
  or mention to the right object; aliases, block links, nesting, tags, the PNG) and out (zero
  dangling links by the documented resolver); golden diffed; the human opening is a recorded manual
  check.
- _rebuilding from files/ alone reproduces every object, field, relation and block:_ `rebuild.rs`: a
  random vault with every field kind, non-field relations, nested blocks and Trash → `pump_out` →
  empty vault → `rescan()` → canonical snapshot (objects with `deleted_at`; fields by kind;
  relations as `(src, dst, rel_type, field key, block, label, props)`; blocks by `id`, kind,
  content, **parent**, order; `created_at` excluded); `verify(true)`; a second `pump_out`
  byte-equal.
- _fuzzing of the Markdown/frontmatter parser:_ layer 1, `fuzz.rs`, every run, proptest (arbitrary
  bytes, structured frontmatter, mutations of valid files): no panic, a time bound, size and depth
  caps, bytes untouched on `Err`; layer 2, a `fuzz/` crate with `cargo-fuzz` (nightly: recalled) on
  the schedule.
- _path traversal and malicious files (brief 288-289):_ `security.rs` over `fixtures/malicious/`:
  each rejected or contained, nothing touched outside the root.
- _inbox kinds and cloud names:_ `inbox.rs`: every kind, `parse_error` holding writes, the four
  vendors' names. _Drop zone:_ `drop.rs`.
- _full export then import reproduces the vault:_ `roundtrip.rs` in the export crate: the row
  snapshot (the helper at `crates/store/tests/common/mod.rs:84` moves to a `test-util` feature), the
  hash chain, `vault_id`, `verify(true)`. _Migration 2→3:_ `migrate.rs`.
- _the two surfaces:_ `mirror.spec.ts`, both sizes, axe.

**Risks.** **The `notify` licence:** CC0-1.0 is outside the allow-list and no maintained alternative
is known (recalled); a C watcher is constrained by the mobile cross-compile and the licence policy,
not by `Cargo.toml:51`, which forbids `unsafe_code` in workspace crates only. **A normalising round
trip:** someone else's Markdown is rewritten in the app's form on the next app-side edit, never on
an inbound apply; the golden shows what changes. **The file shape** (Decisions 4, 8, 8b, 10) is
frozen at gate 1h, since changing it later rewrites every file. **Stale editor buffers:** an editor
that saves an old buffer after the app wrote looks like a clean revert; Obsidian reloads, and
ADR-0021 names this as the one uncovered case. **The 2 s budget** is gated on one OS; **the
10,000-case run's time** is unknown until gate 1f; **`base_text`** doubles the corpus (ADR-0006
64-65).

## Decisions to confirm

   table in M6.
2. Inbound commits off the undo stack (a flagged deviation from brief 145).

   there. The envelope keys, `relations`, `links`, `fields`, and Obsidian's `aliases` and
   `cssclasses` are reserved; a user field whose key is reserved is written under `fields:`, which
   the parser reads as well, so both shapes load.

   - 5b. Tags as `tagged` relations to `Tag` objects by title.
6. Same-named keys for the seven unlisted `objects` columns.

8. Anchors on every block: on the line for paragraphs, list items and images; on their own line,
   with a blank line before and after, for headings, fences, dividers, quotes and tables (gates 1b
   and 1h).
   - 8b. A `links:` list for relations with no field.
9. Attachments as `![[attachments/<hash><ext>]]` embeds.
   - 9b. Sensitive objects default to `excluded`.
10. Path-form mentions always, with `shown`, `block` and `embed` keys on the run.
    - 10b. Unknown frontmatter keys under `props_json._frontmatter`.
11. An empty paragraph written as its anchor alone.
    - 11b. Nesting indents by the parent's marker width (two under `- `, three under `1. `),

12. Identity `id` → path → hash → new; nothing is ever trashed on an inference.
13. An unknown `id` is adopted, a trashed `id` restored, a duplicate re-issued.
14. A file in a folder with no `.md` beside it parents to the folder's parent.
15. The basic drop zone: an object typed by MIME with the blob attached, no extraction.

    - 16b. Trash under `files/.dbme/trash/<id>.md`, returned on restore.

**Detection rules** (plain `str` methods; the workspace has no regex crate), each with a confidence
the inbox shows:

1. **Dropbox, likely.** The last ` (` before `conflicted copy ` or `'s conflicted copy)` or
   ` (conflicted copy)`; with a date, the ten bytes after the phrase are `DDDD-DD-DD` followed by
   `)`. The undated forms rank "possible". Localised phrases are a configurable list, unverified
   until seen on disk.
2. **OneDrive, likely.** The stem ends in `-<host>` (the local device name, compared
   case-insensitively) and the sibling `<stem minus -host>.<ext>` exists. Office extensions are not
   skipped (Microsoft's own example is `.xlsx`), only ranked lower.
3. **Syncthing, certain.** `.sync-conflict-` in the **full name**, then exactly `DDDDDDDD-DDDDDD-`
   and seven of `A-Z2-7` (or none), then the extension or nothing. The base name is the text before
   the marker plus the extension.
4. **Nextcloud, certain.** `(conflicted copy` … `DDDD-DD-DD DDDDDD)`, the user between them
   optional; legacy `_conflict-DDDDDDDD-DDDDDD`; `(case clash from`.
5. **Resilio, possible, and a name clash rather than an edit conflict.** `.Conflict` as the last
   component or before the extension, stripped repeatedly.
6. **iCloud macOS, possible.** `<base> <n>` with n ≥ 2, no leading zero, and the sibling
   `<base>.<ext>` exists.
7. **iCloud Windows, possible.** `<base> (n)` or `<base>(0n)` with the sibling present; forum
   evidence only.
8. **Google Drive: no rule shipped.** The name must be established empirically (one file edited
   offline on two machines) before `cloud_conflict_file` claims support.

**False-positive risks:** a note titled "Draft (conflicted copy)" trips rule 1's undated branch;
"Chapter 2" or "Meeting (1)" trip rules 6 and 7 unless the sibling exists, and even then a person
may keep both deliberately; `todo-laptop.md` on a machine named `laptop` trips rule 2;
`merge.Conflict.md` trips rule 5. Dropbox also writes unrelated tags ("Case Conflict",
selective-sync conflicts on folders) that are not edit conflicts. Syncthing's and Nextcloud's
fixed-width timestamps make theirs the only rules with negligible risk.
