# M2: Editor and basic views

**Status:** done. Merged into `main` on 2026-10-25 by PR #4 (merge commit `33603f9`), after
every CI job passed (run 40253855065). Seven decisions still wait on the maintainer (Deviations
below). **Started:** 2026-10-25, on branch `m2-editor-views` from `main` at `14ed342` (M0
follow-ups and M1 merged).

## Plan

**Scope (handoff brief §8):** the block editor, the Document, Outline, Table (virtualised) and
Gallery views, the hierarchy sidebar, and backlinks.

**Acceptance:** live consistency across views; a 100k-row table at 60 fps; everything
keyboard-operable; every view passes e2e tests at 360 px width with touch input.

**Tasks.**

1. **Store additions** (`dbme-core`, `dbme-store`), tested like M1:
   - Block format: the block kinds of M2 and the shape of `content_json` (inline runs with marks and
     mentions), checked by core, and written into FORMAT.md.
   - New blocks may carry an ID made by the client. The editor needs a block's ID the moment the
     block exists, before any round trip.
   - Mentions become relations: writing a block keeps its `mentions` relations in step with the
     mentions in its content, in the same undo step.
   - Paged reads for large lists: objects by parent or by type, sorted, with offset and limit, and
     counts; children with child counts for the sidebar; a title search for the mention picker;
     backlinks with their source titles.
2. **Command layer** (`crates/api`, new): the session and every vault command move out of the Tauri
   crate into plain Rust functions. The Tauri commands become one-line wrappers. New commands cover
   moves, field values, types, blocks (one batch per editor flush), relations, backlinks, paged rows,
   title search, attachments and blob bytes. Each command gets a `build.rs` entry and a capability
   grant (ADR-0010).
3. **E2E harness:** a test-only HTTP server (`crates/e2e-server`) runs the same command functions on
   real vaults. An e2e build of the UI routes its IPC to that server through Tauri's IPC mocks. The
   server sends the app's Content-Security-Policy, so a CSP violation fails the test. Playwright runs
   Chromium and WebKit at 1280×800 and at 360×740 with touch. A check proves the e2e transport is
   absent from the production bundle.
4. **UI packages:**
   - `packages/client`: the generated bindings, which move here, plus query hooks and the
     `vault-changed` listener.
   - `packages/ui`: shared components on Radix primitives, and tokens.
   - `packages/views`: the view registry and every view.
5. **Shell:**
   - The hierarchy sidebar: a lazy, virtualised tree, keyboard-operable as an ARIA tree, with
     drag-and-drop moves plus a "Move to…" action for keyboard and touch.
   - A view switcher, and a split pane on wide screens to show live consistency.
   - Undo and redo.
   - On phones, the sidebar becomes a drawer.
6. **Document view:**
   - The title, properties, and the block editor: TipTap/ProseMirror mapped to the block tree.
   - Typing is batched into one transaction per flush. Ctrl+Z is the vault's undo.
   - `[[` inserts a mention.
   - Backlinks.
7. **Outline view:** the object hierarchy as an outliner. Enter adds a sibling, Tab and Shift+Tab
   indent and outdent, Alt+↑/↓ move, and sort keys are rebalanced when they grow long.
8. **Table view:** TanStack Table and TanStack Virtual over paged IPC, with keyboard grid
   navigation, inline editing of field values, and sorting. The source is the children of an
   object, or every object of a type.
9. **Gallery view:** a virtualised card grid over the same source. Covers come from image
   attachments, read as bytes over IPC and shown through `blob:` URLs, which the CSP allows.
10. **Tests and budgets:**
    - Unit tests (Vitest) and property tests of the editor mapping (doc → blocks → doc).
    - Per view, e2e tests at desktop and phone sizes: keyboard-only, touch, and cross-view
      consistency, with axe on every view.
    - A UI budget job: a 100k-row table scroll at 60 fps, measured in Chromium from frame timings
      plus a performance trace. Typing latency is measured against the 16 ms budget.
11. **Close-out:** the acceptance checklist; screenshots at desktop and phone sizes; this file.

**ADRs.**

- **ADR-0016, blocks and the editor:**
  - Why TipTap: core only, MIT, no Pro extensions.
  - The block kinds and the `content_json` shape.
  - Nesting under list items.
  - Client-made block IDs.
  - Mentions as relations.
  - No editor-local history: undo is the vault's.
- **ADR-0017, UI architecture:**
  - The packages.
  - Zustand for UI state and TanStack Query for vault reads.
  - Refreshing active queries on `vault-changed`.
  - Paged reads.
  - Styling under the strict CSP: no injected `<style>`; TipTap's `injectCSS` off; Radix
    primitives only in modes that inject no style elements.
- **ADR-0018, the e2e harness:**
  - The command layer and the test server.
  - Playwright browsers as stand-ins for the webviews.
  - CSP enforced in tests.
  - The UI budget method.
  - The deviation from tauri-driver, and why.

**Risks.**

- **CSP and libraries.** Some libraries inject `<style>` elements, for example the scroll lock
  behind Radix's modal dialogs. These are blocked in the app. The e2e server sends the real policy
  so that tests catch them.
- **Editor and store disagreeing.** A split or a paste can duplicate an ID. An undo, or an edit
  from another view, can land while the user is typing. The editor mapping is pure and
  property-tested. The editor flushes before it applies a change from outside, and it ignores the
  echo of its own writes.
- **Mobile input.** Playwright's touch emulation runs desktop engines. Real phone keyboards and IME
  composition are not covered until M14.
- **60 fps on CI.** Headless runners are noisy and are not the reference machine. As with the Rust
  budget, the gate may need a margin and a measured, ungated companion.
- **Fidelity of the e2e tests.** Playwright's Chromium is close to WebView2. Its WebKit only
  approximates WKWebView and WebKitGTK. The real app stays covered by the launch test on all three
  operating systems.
- **Size.** This is the largest UI milestone. The work lands in stages, each with its tests.

## What was built

- **Store:** the block format (FORMAT.md §3.5) checked by core; block IDs made by the client;
  mentions kept as relations in the same transaction; paged reads (objects by parent or type,
  sorted, with counts), child counts, title search, backlinks and ancestors; sort keys rebalanced
  in the same step when they grow past 16 characters.
- **`dbme-api`:** 31 commands as plain functions over a session. The Tauri commands are one-line
  wrappers, each listed in `build.rs` and the capability file.
- **UI packages:** `@databaseme/client` (bindings, queries, live refresh, ULIDs, the e2e
  transport), `@databaseme/ui` (tokens, components on Radix and the native `<dialog>`, icons) and
  `@databaseme/views` (registry, Document, Outline, Table, Gallery, sidebar, editor, field
  editors).
- **Shell:** the sidebar tree with drag-and-drop and "Move to…", view tabs, a split pane from
  1,100 px, undo and redo, and a drawer below 768 px.
- **E2E harness:** `dbme-e2e-server`, the e2e build, Playwright on Edge and WebKit at two sizes,
  axe, the CSP check, and the two UI budgets; a Windows CI job runs them.
- **Docs:** ADR-0016 (blocks and the editor), ADR-0017 (UI architecture), ADR-0018 (e2e harness
  and UI budgets); FORMAT.md draft 2 (§3.5); "Later changes" notes on ADR-0010, ADR-0013 and
  ADR-0014; ARCHITECTURE.md's code map; CHANGELOG.

Bugs found and fixed while closing the milestone:

- **Formatting toolbar dead to touch on WebKit.** Cancelling `pointerdown`, to keep the editor's
  selection, made WebKit drop the tap's click. On an iPhone or iPad the toolbar would have done
  nothing. It now cancels `mousedown` instead.
- **Mentions stuck at "…".** After the Document view came back, or opened in a second pane, a
  mention whose title was already cached never showed it until the next change. `observeTitle`
  now reports the cached title at once. A unit test and an e2e test cover it. The screenshots
  found this; the earlier tests checked mentions only on first load or after a change.

## Deviations and decisions to confirm

1. **No performance trace in the budget job.** The plan said "frame timings plus a performance
   trace". The budgets use frame timings only, because they pass with a wide margin. A trace is
   the tool for when one fails (ADR-0018).
2. **Edge, not Playwright's Chromium.** Edge is the engine WebView2 ships, so it is the closer
   stand-in (ADR-0018).
3. **Budgets enforced on Edge desktop only.** WebKit's Windows build is a test port, not WKWebView,
   so its numbers are recorded and not enforced. The budgets run in their own projects, after the
   functional tests, one test at a time.
4. **One WebKit CSP report excused.** Playwright's WebKit 27.2 reports `style-src-attr` against
   every `<select>`. It comes from the engine's own styling of the control and happens even with
   bare markup and no app code. The fixture excuses exactly that report, on WebKit only. It must
   be checked again in a real WKWebView (ADR-0018).
5. **The e2e CI job runs on `windows-latest`,** like the reference machine, with Edge from the
   runner and WebKit installed by Playwright.
6. **Accepted ADRs get "Later changes" notes.** ADR-0010, ADR-0013 and ADR-0014 have facts that M2
   changed: the commands granted, automatic rebalancing, and where the bindings live. Each gets
   a dated note pointing to the new ADRs, instead of a rewrite or a superseding ADR. Confirm this
   pattern, or name the one you prefer.
7. **No JS coverage figure.** No coverage provider is installed. Adding `@vitest/coverage-v8`
   (MIT, dev only) would give one; it is a new dependency, so it waits on your word.

## Known issues

- **WebKit table scroll at 25–48 fps** on Windows: reading 48 fps and flinging 41 fps locally,
  30.5 and 25.3 fps on CI. Recorded, not enforced. It would fail the Edge budget by a wide margin,
  but this is Playwright's Windows test port. The real targets are WKWebView (macOS, iOS) and
  WebKitGTK (Linux), which nothing here measures yet.
- **A WebKit worker hung once at exit.** In one run that put the budgets beside other tests, a
  WebKit worker waited on an orphaned `WebKitNetworkProcess` for over 15 minutes and had to be
  stopped. Two later runs did not repeat it. The config now has a 30-minute global timeout, and
  the CI job a 60-minute limit.
- **The Edge budgets have one run of history on CI.** The first run passed, but the 60 Hz runner
  leaves the table's median about 10% under its limit, and one key took 21 ms. If they flake,
  they get a margin and an ungated companion (ADR-0018).
- **The phone view tabs clip "Gallery"** at 360 px. The strip scrolls sideways, and every tab is
  reachable and tested, but the clip looks unfinished.
- **Coverage gaps as in M1:** core's `seed.rs` 65.6%; store's `identity.rs` and `sql.rs` about 85%.
- **Local environment only:** Playwright's own browser downloader stalls on this machine. WebKit
  2370 was fetched with curl from Playwright's CDN, checked, and unpacked by hand. Early in the
  milestone, running `msedge.exe --version` opened the maintainer's Edge session.
- WebView2 still prints `Failed to unregister class Chrome_WidgetWin_0` on smoke-mode exit
  (harmless, as in M0 and M1).
